# 전력 피크 관리 표준작업절차서 (SOP)

적용 대상: 15분 단위 수요전력을 측정하는 제조 공장. 이 문서의 수치는 2021년 데이터로 산출했으며 단위는 데이터의 기록 단위이다(15분 수요전력으로 간주, 에너지는 기록 단위 × 시간). 기계가 읽는 형태는 `agent/sop.json`에 있다.

## 1. 목적

- 15분 최대수요전력이 상한(분석 기준값 190)을 넘기 전에 경보를 내린다.
- 현장이 무엇을, 얼마나, 언제까지 할지 정한다.
- 모든 조치는 작업자가 승인하며, 시스템은 제안만 한다.

## 2. 시스템 구성

```
예측 모델 ──▶ 2단계 경보 ──▶ SOP 조치 제안 ──▶ 검증(피크 상한 시뮬레이션) ──▶ 작업자 승인 ──▶ 결과 기록
 (매시 갱신)    (적색/황색)     (이연량 산정)       (실패 시 대체 조치)                          (주간 재학습에 반영)
```

| 구성 요소 | 내용 |
|---|---|
| 다음 시간 예측 | LightGBM, 매주 재학습. t시 시작 시점에 t-1시까지의 데이터로 t시의 15분값 4개 예측 |
| 하루 전 예측 | 가동 캘린더(가동/휴지)를 반영한 다음 날 24시간 예측 |
| 적색 경보 | 피크 분류기 (확률이 기준값 이상) |
| 황색 경보 | 시계열 규칙(08–11시 또는 13–14시이고 직전 시간 평균이 100 이상) 또는 다음 시간 90% 예측 구간 상한 ≥ 190 |
| 에이전트 | 브리핑, 경보, 조치 제안과 검증, 질문 응답, 결과 기록. 모든 숫자는 도구 결과에서만 가져옴 |

## 3. 경보 단계

| 단계 | 의미 | 담당 | 대응 시간 | 조치 |
|---|---|---|---|---|
| 🟢 정상 | 위험 신호 없음 | – | – | 정상 운전. 재량 부하 기동은 가능하면 위험 시간대 밖으로 |
| 🟡 주의 | 시계열 규칙 발동, 또는 다음 시간 90% 예측 구간 상한 ≥ 190 (분류기 신호 없음) | 현장 반장 | 15분 | 새 재량 부하 기동 보류, 이연 가능 부하 준비, 다음 시간 경보 확인 |
| 🔴 경고 | 분류기가 피크 가능성 높다고 판단 | 현장 반장 → 설비 담당자 | 5분 | 제안된 이연량 실행(검증 통과 시), 재가동 설비는 15분 간격 순차 기동 |

황색은 피크 첫 시간을 잘 잡고(38개 중 34개), 적색은 정밀도가 높다(적색 시간의 56%가 실제 피크). 한쪽만 쓰지 않는 이유다.

## 4. 시간대별 절차

### 4.1 전일 (자정, 다음 날 예측 발행 시점)

| 조건 | 근거 (2021년 6–7월, 테스트 이전) | 조치 |
|---|---|---|
| 휴지 후 첫 가동일 | 피크 발생률 14.6% (일반 가동일 9.6%) | 오전 기동과 점심 후 재기동을 15분 간격으로 나누어 계획 |
| 최고기온 28 °C 이상 예보 | 피크 발생률 15.9% (그 외 5.4%) | 공조 예냉을 07시 이전에 실시, 13–14시 재량 부하 금지 |
| 하루 전 예측 + 여유 15.3이 190 이상인 시간 | 하루 전 예측의 7월 오차 중앙값 15.3 | 해당 시간의 재량 부하 일정을 오후 늦게로 이동 |

### 4.2 한 시간 전 (매 정시, 다음 시간 대상)

- 경보 단계가 **올라갈 때만** 사전 경보를 보낸다(정상→주의, 주의→경고). 이미 적색이 이어지는 동안에는 반복하지 않는다.
- 🟡 예상: 다음 시간 재량 부하 기동 보류 준비
- 🔴 예상: 이연할 부하를 지정하고 담당자에게 통보

### 4.3 이번 시간 (매 정시)

- 🟡: 새 재량 부하 기동 보류
- 🔴: 5절의 이연량을 산정하고 검증한 뒤 실행

## 5. 이연량 산정과 검증

**산정 (적색일 때)**

- 예상 최대 = 다음 시간 예측 + **23.6**. 23.6은 7월 피크 시간에 예측이 실제보다 낮았던 폭의 중앙값이다. 예측은 피크를 과소예측하는 경향이 있어 이를 보정한다.
- 15분 구간별 감축량 = max(예상값 − 190, 0)
- 제안 = 이번 시간 최대 감축량, 그리고 이연 에너지 = 감축량 합 ÷ 4

**검증 규칙** (에너지 보존, 예측 기반)

1. 이연한 에너지는 이후 시간의 여유(190 − 하루 전 예측 − 15.3)에만 재투입한다.
2. 다음 시간도 적색이면 그 시간에는 재투입하지 않는다.
3. 위험 시간대(08–11시, 13–14시)에는 재투입하지 않는다.
4. 같은 날 앞선 조치가 이미 쓴 여유는 다시 쓰지 않는다(여유 원장 관리).
5. 최대 4시간 이내, 22시 이전에 모두 재투입되어야 통과한다.

**검증 실패 시 대체 조치**

1. 다음 배치 기동을 점심(12시) 또는 15시 이후로 연기
2. 비필수 부하(조명 일부, 공조 설정 완화)를 이번 시간 동안 감축(재투입 없음)
3. 설비 담당자에게 수동 판단 요청

## 6. 부하 우선순위 표 (도입 시 가장 먼저 작성)

데이터에는 설비 정보가 없으므로, 도입 첫 단계에서 공장이 직접 작성한다.

| 등급 | 설명 | 이연 가능 | 최대 이연 |
|---|---|---|---|
| A | 중단 불가 (프레스 라인, 안전 설비) | 아니오 | – |
| B | 짧게 이연 가능 (공기압축기 + 버퍼 탱크, 냉각수 펌프) | 예 | 30분 |
| C | 길게 이연 가능 (배치 가열, 충전, 공조 예냉) | 예 | 4시간 |

재생 검증에서 최대 이연 시간을 줄이면 통과율이 크게 떨어졌다: **1시간이면 76건 중 24건, 2시간이면 45건, 4시간이면 76건 모두 통과.** 적색 조치는 주로 C등급 부하로 수행해야 하며, B등급만으로는 부족한 경우가 많다.

## 7. 기록과 재학습

- 매시 종료 후 실제 최대값, 경보 단계, 판정(적중 / 오경보 / 미탐지 / 주의 단계 발생)을 기록한다.
- **다음 시간 예측 모델: 매주 재학습.** 테스트 기간에 MAE가 6.30에서 6.07로 개선되었고, 7주 중 첫 주를 제외한 모든 주에서 좋아졌다.
- **피크 분류기: 느린 주기로 재학습하고 기준값 변화를 감시한다.** 주간 재학습으로는 개선이 뚜렷하지 않았고, 기준값이 0.15에서 0.29로 올라갔다.

## 8. 에이전트의 역할과 안전장치

| 원칙 | 구현 |
|---|---|
| 숫자는 도구에서만 | 모든 메시지는 사용한 숫자를 '근거'로 기록하고, 문장 속 모든 숫자를 근거와 대조한다 |
| 조치는 검증 후에만 | 이연 제안은 5절의 검증을 통과해야 표시되며, 실패하면 대체 조치로 바뀐다 |
| 사람이 결정 | 에이전트는 제안만 하고 설비를 직접 제어하지 않는다 |
| LLM은 선택 사항 | 기본은 규칙 기반(템플릿)이며 API 키 없이 동작한다. LLM을 연결하면 LLM이 도구 결과로 답을 쓰고, 근거 없는 숫자가 있으면 거부하고 템플릿 답변을 보인다 |

에이전트가 답하는 질문 유형: "왜 경고야?", "지금 뭘 해야 해?", "오늘 브리핑", "비슷한 과거 날은?", "다음 시간 상태는?"

## 9. 재생 검증 결과 (2021-08-01 ~ 09-14, 45일, 가동일 32일)

| 항목 | 결과 |
|---|---|
| 피크 시간 중 적색 또는 황색 경보가 있던 시간 | 68개 중 68개 (예측 구간 황색 포함; 규칙+분류기만으로는 64개) |
| 피크 첫 시간 중 한 시간 전에 경고가 있었거나 이미 적색이던 경우 | 38개 중 28개 |
| 피크 첫 시간 중 해당 시간에 적색 또는 황색이던 경우 | 38개 중 38개 |
| 상한 초과 에너지 중 적색·황색 시간에 발생한 비율 | 100% |
| 적색 조치 중 제안 감축량이 실제 필요량 이상이던 피크 시간 | 43개 중 40개 |
| 평균 제안 감축량 / 평균 실제 필요량 (피크 시간) | 19.0 / 5.2 (보수적) |
| 작업자 대상 메시지 (가동일당) | 7.8건 |
| 근거 확인 통과율 (전체 메시지) | 100% |
| LLM 안전장치 (스크립트 시험) | 근거 없는 숫자(99%, 50, 120만 원)를 포함한 답변을 거부하고 템플릿으로 대체 |

감축 제안이 실제 필요량보다 평균 약 3.7배 크다. 7월의 큰 과소예측 폭(23.6)을 여유로 쓰기 때문이다. 여유를 줄이면 제안이 작아지는 대신 부족한 경우가 늘어나므로, 공장이 운영 경험을 쌓으며 조정할 값이다.

## 10. 도입 단계 (새 공장)

| 단계 | 기간 | 모델 | 근거 |

## 11. 데이터 품질·이상 부하 감시

매 정시에 방금 끝난 시간을 점검한다. 모든 기준은 테스트 이전(1~7월) 데이터로 정했다.

| 점검 | 규칙 | 근거 | 조치 |
|---|---|---|---|
| 0값 | 15분값 중 0이 있음 | 1~7월에 0값이 한 번도 없음 (유휴일도 약 20) | 계측기·통신 확인 |
| 멈춤 | 같은 값이 8구간(2시간) 이상, 값 35 이상 | 가동 수준에서 1~7월에 없음 | 계측기 확인 |
| 급변 | 15분 사이 변화가 94 초과 | 1~7월 15분 변화의 99.9% 분위 | 계측기 또는 설비 급정지 확인 |
| 이상 부하 | 실제 평균과 예측 평균의 차이가 최근 28일 차이의 상위 1% 초과 | 7월 값으로 시작해 매시 갱신 (과거 완료 시간만 사용) | 계획 외 가동·정지 확인 |

- 측정 이상은 **발생할 때와 정상으로 돌아올 때만** 알린다.
- 이상이 생기면 이후 3시간 동안의 예측과 경보에 "신뢰도 낮음" 문구를 붙인다. 예측 모델이 최근 3시간 값을 입력으로 쓰기 때문이다. 입력에 이상이 있던 시간의 예측 오차는 **18.0**으로, 정상 입력일 때의 **5.8**보다 약 3배 컸다.
- 예측 입력 자체가 이상했던 시간은 이상 부하로 판정하지 않는다. 이상 측정 때문에 생긴 예측 차이를 설비 이상으로 오인하지 않기 위해서다.
- 재생 결과 (8/1~9/14): 0값이 있던 20시간을 모두 탐지해 사건 2건(8/28~29 약 18시간, 9/8)으로 보고했다. 이상 부하 알림은 4건으로, 모두 주말 가동 상태 전환(토요일 오전 저부하, 일요일 정지, 토요일 새벽 가동)에서 발생했다. 1~7월에는 4,896시간 중 21시간(0.4%)에서 급변 규칙이 발동했다.

## 12. 요금 제도와의 연결 (근거: docs/KEPCO_and_related_work.md)

- **운영 기간:** 기본요금은 직전 12개월 중 12·1·2·7·8·9월과 당월의 15분 최대수요전력 가운데 최대값으로 정해진다(기본공급약관 제68조). 이 데이터의 최대값 222는 7월 19일(고유일)과 1월 29일(복제된 반복 프로파일)에 기록되었고, 한 번의 222가 이후 1년간 기준이 된다. 따라서 경보와 SOP는 **동계(12~2월)와 하계(7~9월) 여섯 달 모두에 운영**해야 기본요금이 줄어든다.
- **재투입 시간대:** 2026년 4월 시간대 개편으로 18~21시가 최대부하 요금 시간이 되었다. 실제 도입 시 이연한 부하를 18~21시에 재투입하지 않도록 5절 검증 규칙에 이 시간대를 추가한다.

## 13. 한계

- 재생 검증은 경보와 제안이 실제 상황과 얼마나 맞았는지를 측정한다. 작업자가 조치를 실행했을 때 피크가 실제로 줄었는지는 이 데이터로 확인할 수 없다.
- 단위와 계약전력은 확인되지 않았다. 190은 분석 기준값이다.
- 최고기온은 기록값을 예보 대신 사용했다.
- 가동 캘린더(가동/휴지)는 공장이 하루 전에 안다고 가정했다.
- 테스트 기간은 개발 중에 조회되었으므로 결과가 다소 낙관적일 수 있다.
